# Contributing to Deepshaft

Thanks for your interest in improving Deepshaft.

## Copyright assignment (required)

By submitting a contribution (a pull request, patch, or any other change) you
**assign the copyright in that contribution to Ben Richardson**, and you confirm
you have the right to do so. This keeps the copyright in the project held by a
single party, so the project can continue to be offered under both the
[GNU AGPL-3.0-or-later](./LICENSE) and a separate commercial licence (see
[ADDITIONAL-TERMS.md](./ADDITIONAL-TERMS.md)).

If you cannot assign copyright, please open an issue to discuss before sending a
pull request.

## Ground rules

- Keep the game **self-contained**: no CDN assets, no third-party fonts, no
  trackers beyond the existing Cloudflare Web Analytics beacon and the hosted
  feedback widget. Every texture, sprite, icon and sound is generated by code in
  this repository at boot.
- The shared engine (`@ben-gy/game-engine`) is a **dependency** — never vendor or
  edit it from here.
- Run `npm test` and `npm run build` before opening a pull request; both must pass.
  `tests/balance.test.ts` takes about seventy seconds. That is the price of the
  gate below, and it is much cheaper than the alternative.

## The numbers in this repository were measured, not chosen

Several constants look arbitrary and are not. Changing one means re-running the
simulation that produced it, never editing the expectation. Four of them were
measured, produced a result nobody expected, and changed the design:

- **`partyScale` exists at all.** With a flat horde, three players were
  **immortal**: 73% of three-player runs were still going at the seven-minute
  limit, because three guns on one player's worth of enemies out-killed the ramp
  and out-revived the damage forever. The depth metric could not see it — a run
  that never ends has no depth to report. It also does the opposite job at the
  other end, so a solo run gets *less* than a nominal floor rather than the same.
- **The pressure wave GROWS, it does not merely accelerate.** Shrinking the gap
  between waves took non-termination from 45% to 6.7% and stalled there. Adding
  `burst` — more enemies per wave the longer a floor drags — took it to zero.
- **The pressure spawn fires even when every candidate is in sight.** The first
  version gave up silently after twelve tries; on a small floor with three players
  spread across it, twelve tries in a row are *all* visible, so the wave that was
  meant to end the stalemate never arrived at all. Being seen arriving is a much
  better outcome than the mine having no way to close a run.
- **`hpKnee`/`hpGeom`.** A purely linear HP ramp against a party whose damage
  output is roughly constant is a race the party eventually wins forever. The
  geometric tail past floor 5 is the term that guarantees a run terminates.

Also measured and load-bearing: the three **negative-GAP arms** in
`tests/balance.test.ts`. A bot blinded to retreating, to weapon choice, or to
reviving must do measurably *worse*. If one of those ever goes flat, that mechanic
is decoration and the right response is to cut it, not to widen the tolerance.

## Three bugs that only a test could have found

- **3.2% of generated floors were unsolvable.** `mine.ts`'s header used to claim
  the lock/key deadlock was "unreachable by construction". The argument was sound
  on the spanning tree and the tree is not the grid: overlapping corridors and a
  door-placement walk that disagreed with the carve walk put keys behind their own
  doors. It is now a claim that is *checked* — `verifySolvable()` runs the same
  fixed-point flood a player performs, and a floor that fails is re-rolled with
  fewer locks. Do not replace it with an argument.
- **Sampled line-of-sight is not line-of-sight.** The game's `clearLine` sampled
  the segment eight times per cell, and shots went through pillar corners — twice
  in a single three-minute run. It is a grid DDA now, which has no sampling rate to
  get wrong and is *cheaper*. The auditor in `tests/helpers/sim.ts` independently
  uses Liang–Barsky slab clipping; it must never be changed to call the game's own
  raycast, because an audit that checks the game against itself passes on a
  completely broken game.
- **The tutorial descended off its own floor.** Walking onto the cage on the last
  step dropped the player into a freshly generated Adit floor 2, mid-sentence.
  `Game.stairEnds` exists for that, alongside `Game.noDeath` — a teaching sequence
  that can kill you on step two is not a teaching sequence, and the first build did
  exactly that.

## Two rules in the renderer that must not be "polished"

- **Walls fog with distance. Sprites do not.** Contrast is
  `(L1+0.05)/(L2+0.05)`, so multiplying a monster and the wall behind it by the
  same distance factor drives their ratio toward 1:1 — a body drawn correctly, in
  the right cell, at the right size, and *invisible*. `spriteFog()` is pinned at a
  constant 1 by `tests/contrast.test.ts`. Distance is carried by size, which is a
  channel fog cannot eat.
- **The simulation is driven by a `setInterval` backstop, not only by rAF.** A
  browser stops firing rAF the moment a tab is backgrounded, and this game is
  host-authoritative: a host who switches tabs would freeze the mine for the whole
  crew. rAF is a render signal, never a clock. The catch-up budget is a full second
  because a background tab clamps timers to roughly 1Hz — at the original 8-step
  cap a backgrounded host ran the mine at 17% speed.

## Layout

`tests/layout.test.ts` ratchets the CSS invariants, including
`[hidden] { display: none !important; }` (Safari's UA rule is not `!important`, so
a class that also sets `display` leaves an invisible layer eating every tap) and
`min-width: 0` on the HUD row's children — without it the Skip button was pushed
half off the right edge of a 375px screen, on the one screen a player most needs an
escape from.
